# Scheduled occurrences are projections; transactions are created on the due day

A Recurring transaction creates a real Transaction only on each occurrence's due day (catching up the missed days whenever the app opens). Occurrences dated after today appear in Future as read-only Scheduled rows computed from the schedule, and they count in no balance or report. We rejected pre-creating future-dated Transactions: every edit to the schedule, amount, wallet or end would have to find and rewrite many real rows, and a forever-repeating item has no finite set of rows to create. The cost is that Future now mixes real Transactions with computed rows, so Scheduled rows are capped (at most 12 per Recurring transaction, within a year) and open the Recurring transaction rather than a transaction editor. The one exception to "created on the due day" is the start-date prompt: occurrences from a past start date through today become Transactions only if the user selects them, and only when they save.
