# Scheduled occurrences are projections; transactions are created on the due day

A Recurring transaction creates a real Transaction only on each occurrence's due day (catching up the missed days whenever the app opens). Occurrences dated after today appear in Future as read-only Scheduled rows computed from the schedule, and they count in no balance or report. We rejected pre-creating future-dated Transactions: every edit to the schedule, amount, wallet or end would have to find and rewrite many real rows, and a forever-repeating item has no finite set of rows to create. The cost is that Future now mixes real Transactions with computed rows: a forever-repeating schedule lists only its next Scheduled row, an ended one lists every payment still to come, and Scheduled rows open the Recurring transaction rather than a transaction editor. The one exception to "created on the due day" is the start-date prompt: occurrences from a past start date through today become Transactions only if the user selects them, and only when they save.

Note: the Month graph is a second reader of the schedules. For the current period it expands every active schedule paid from the selected wallets through the period's last day, every Occurrence rather than only the next one of a forever-repeating schedule, to draw its dotted line and Expected by month end. Home's graph is a month and counts the Total; the comparison card on Income and Spent details covers a week, month, quarter or year and counts the Wallet selector's choice. Both still compute them on demand, with the same end and "dealt with" rules as the Scheduled rows, and store nothing: the projection changes no balance, report or Transaction.
